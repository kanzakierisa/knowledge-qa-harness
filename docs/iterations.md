## 四、逐轮迭代记录

### 迭代 1（`generate/prompt.go`：Prompt v2 → v3）

- **改动**：仅修改 [generate/prompt.go](../generate/prompt.go) 的 `BuildPrompt`（Prompt v2 → v3）：

  2. 规则 2 增加“若资料中的条款可直接推导出答案（包括数值边界与功能优势），或提问前提与资料不符但资料明确说明了实际行为（如失败时 panic 而非返回 error），请直接依据资料作答或纠正，不要误拒”。
- **原因**：针对迭代 0 中的 4 个生成侧问题（`q_id=39` 越界总结推论、`q_id=28/33/37` 查到 Top 1 仍保守误拒）。
- **结果**（`run_id = 78..129`）：
  - 检索命中率：`95.00% (38/40) → 95.00% (38/40)`（未变，未命中仍为 `q_id=32 (run_id=109)`、`q_id=47 (run_id=124)`）
  - 引用准确率：`100.00% (35/35) → 100.00% (36/36)`
  - 答案可用率：**`97.14% (34/35) → 100.00% (36/36)`（+2.86%）**
  - 拒答正确率：`100.00% (12/12) → 100.00% (12/12)`
  - 误拒数：`5 → 4`（`q_id=28 (run_id=105)` 转为正确作答；`q_id=39 (run_id=116)` 去掉越界外推句后转为 `usable=true`；仅剩误拒 `q_id=32, 33, 37, 47`）
  - **人工标注轻度观察（`q_id=34 / run_id=111`）**：回答为 `不会运行。[1] os.Exit(1) 立即退出且不执行 defer；[1] log.Fatal 打印消息后调用 os.Exit(1)。` 内容全部出自 `go-flag-cli.md` 且无幻觉，但第二个 `[1]` 误放于分号后、导致末尾 `log.Fatal...` 分句结尾缺少 `[1]`，人工标 `true` 并记为轻度格式观察，待在校验层收口。

### 迭代 2（`retrieve/merge.go`：`KeywordNormFloor` `10.0 → 45.0`）

- **改动**：仅修改 [retrieve/merge.go](../retrieve/merge.go) 中的 `KeywordNormFloor` 常量由 `10.0` 调高为 `45.0`（保持 `VectorWeight=0.6`、`KeywordWeight=0.4` 及其他全部逻辑不变）。
- **原因**：迭代 0/1 中 `q_id=32`（`gold_chunk_id=367`）未进 Top 5。因为低分母软下限 `10.0` 会把通用词碰词的 BM25（`maxBM25 ≈ 13.01`）放大成满分 `1.000`，导致关键词权重 `0.4` 覆盖了原本排名第 1 的语义向量分。
- **结果**（`run_id = 130..181`）：
  - 检索命中率：**`95.00% (38/40) → 97.50% (39/40)`（+2.50%）**，`q_id=32 (run_id=161)` 成功召回进 Top 5 第 4 位（`[372,300,315,367,304]`）且完整正确作答（`usable=true`）
  - 引用准确率：`100.00% (36/36) → 100.00% (37/37)`
  - 答案可用率：`100.00% (36/36) → 100.00% (37/37)`（人工逐条确认有变化的 13 条回答全部标 `true`）
  - 拒答正确率：`100.00% (12/12) → 100.00% (12/12)`
  - 误拒数：`4 → 3`（剩余误拒：`q_id=33, 37, 47`）
  - 阈值拒答副收益：阈值直接拦下的无关题由迭代 0/1 的 2 题（`q_id=19`、`q_id=25`）增至 **3 题**（新增 `q_id=21`：“Gin 作者最喜欢的颜色是什么？”，Top1 融合分由虚高降至 `0.3479 < 0.35` 直接触发阈值拒答，省去 LLM 调用）。
  - **人工标注轻度观察（`q_id=34 / run_id=163`）**：回答为 `不会运行。[1] os.Exit(1) 立即退出且不执行 defer。[1] log.Fatal 打印消息后调用 os.Exit(1)。` 与迭代 1 同类——内容全出自 `go-flag-cli.md` 且无幻觉，但第二个 `[1]` 误放于 `log.Fatal...` 一句之前，导致结尾句句末无 `[1]`，人工按 `usable=true` 入库并记录该轻度格式问题。
- **结论**：有效，保留。
- **本迭代学到什么**：`max(maxBM25, KeywordNormFloor)` 中的软下限直接决定了“低绝对 BM25 查询中关键词路的最大杠杆”；把 `KeywordNormFloor` 从 `10.0` 提升至 `45.0` 能让泛词碰词不再被归一化成 `1.0` 满分，同时保留高匹配术语（阶段 3 测试与多词专名查询）的显著加权。但对于极少原词命中的语义改写题（`q_id=47`），仅调分母仍不足以克服 `0.6 / 0.4` 的权重比。

- **结果**（`run_id = 182..233`）：

### 迭代 4（`generate/llm.go`：`ValidateCitations` 句级引用校验强化）

- **改动**：仅修改 [generate/llm.go](../generate/llm.go) 的引用校验逻辑（并在 [generate/audit_stage4_test.go](../generate/audit_stage4_test.go) 补充单测；Prompt 与检索参数均保持不变）：
  1. 在原有“至少有引用 + `[n]` 编号处于 `1..maxN`”基础上，新增句级校验函数 `splitSentencesForCitation` 与 `isAllowedIntroSentence`；
  2. 要求每个实质性陈述句与结尾句必须含 `[n]`（将紧随句末标点后的 `。[n]` 归属前句，并在分号紧邻 `[n]` 时按分句切分，同时兼容同一句内 `；` 并列、句末统一标引的写法）；
  3. 保留对首句 `<= 15` 字引导短句（如 `q_id=31` 的“不能说明数据库已经连接成功。”）与 `示例：` 前缀（非结尾句）的兼容性；若校验不通过则返回包含具体未标引句片段的重试错误提示。
