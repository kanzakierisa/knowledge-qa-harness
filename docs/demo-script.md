# V1 基线 3 分钟演示脚本（历史归档）

> 本文档为 V1 阶段（Go/Gin 单项目基线）的演示脚本归档；当前 V3 完整多项目演示请见 [docs/v2_demo_script.md](v2_demo_script.md)。

## 录屏前准备（开录前 1 分钟检查）

1. 确认 MySQL `knowledge_qa` 已灌入语料（179 段）和 52 道金标评测题。
2. 终端 A 启动服务：
   ```bash
   go run .
   ```
   确认输出 `knowledge-qa 服务启动，监听：:8080`。
3. 浏览器打开 `http://localhost:8080`，缩放 100%，确认右下角显示 `当前语料 179 段` 与最近评测 4 指标。
4. 终端 B 提前切到项目目录，备好演示评测的命令（不要先回车）：
   ```bash
   curl -s -X POST http://localhost:8080/api/eval/run
   ```
5. 编辑器标签页提前打开 `README.md`（定位到“架构”流程图）和 `docs/iterations.md`（定位到“指标变化总览”表格）。

## 分段脚本（00:00 - 03:00）

### 00:00 - 00:20｜痛点引入与演示目标（画面：停在 Web 首页）

- **画面操作**：鼠标微移展示简洁首页（输入框 + 示例标签 + 右下角统计）。
- **口播词**：
  > 团队技术文档越积越多，直接问通用大模型经常遇到“一本正经地胡说八道”，或者不敢确定结论到底出自哪份文档。今天演示的 **Go 知识问答 Agent Harness**，以 Go 和 Gin 官方文档为语料，核心只做两件事：**每句结论强制带来源编号 `[n]` 可一键溯源，资料不足时明确拒答；所有改动由金标评测集的 4 个量化指标驱动，不靠感觉调参。**

### 00:20 - 00:50｜架构图讲解（画面：切到 `README.md` ASCII 架构图）

- **画面操作**：展示 `README.md` 中的核心流程 ASCII 图，顺着箭头的两个阶段指读。
- **口播词**：
  > 整套系统没有用重型编排框架，而是一条每步都可验证的直线流水线。
  > 离线阶段把 `corpus/` 下的 Markdown 按标题层级和代码块保护规则切成 179 个段落，调用 Embedding API 存进 MySQL；
  > 在线问答时同时跑**向量语义检索**和 **BM25 关键词检索**，两路融合取 Top 5：如果最高融合分低于阈值 `0.35`，**直接拒答，根本不调 LLM**；过线才拼进约束 Prompt 让模型作答，返回后还要经过**代码级句级引用校验**——漏标或乱编编号会触发一次带纠错原因的重试，仍不过同样兜底拒答。

### 00:50 - 01:40｜现场提问 2 个：正常引用 + 点击 `[n]` 跳转来源（画面：切回浏览器 `http://localhost:8080`）

- **画面操作 1（00:50 - 01:15）**：
  - 点击或输入第 1 题：`Gin 路由组怎么用？` → 点击“提问”按钮（展示按钮 loading 态）。
  - 答案渲染完成后，停顿 2 秒指着句末 `[1]`、`[2]` 标签与下方参考来源卡片。
- **口播词 1**：
  > 先问一个标准问题：“Gin 路由组怎么用？”。可以看到回答过程中按钮有明确的加载反馈，返回后每句结论末尾都标有 `[1]`、`[2]` 这样可点击的引用编号，下方“参考来源”列出了对应的标题路径和段落原文，标有“已引用”徽章。
- **画面操作 2（01:15 - 01:40）**：
  - 点击或输入第 2 题：`Gin 里怎么绑定 JSON 请求体？` → 点击“提问”。
  - 答案出来后，**点击答案正文中的 `[1]`（或 `[2]`）按钮**，展示页面自动高亮该来源卡片并平滑滚动定位过去；若卡片原文超过 300 字符，顺手点一下“展开全文”。
- **口播词 2**：
  > 再看第 2 题“Gin 里怎么绑定 JSON 请求体？”。如果我想核实某句话是不是模型编的，直接点正文里的 `[1]`，页面会自动高亮并滚动到对应的原始切片；较长的段落默认折叠，点击“展开全文”就能核对原始文档代码和上下文，真正做到每句可溯源。

### 01:40 - 02:00｜演示拒答（画面：浏览器 + 终端 A 日志一眼带过）

- **画面操作**：
  - 点击示例或输入：`怎么做法式红酒炖牛肉？` → 点击“提问”。
  - 页面瞬间出现灰色卡片：`文档中没有依据`，无来源列表。
  - （可选快速切一下终端 A 日志）指出 `[ask] 阈值拒答（Top1 融合分 ... < 0.35），未调用 LLM`。
- **口播词**：
  > 接下来问一个语料完全没有的问题：“怎么做法式红酒炖牛肉？”。系统几乎瞬间返回灰色提示“文档中没有依据”，下方不显示任何伪造来源。看服务端日志可以看到，Top 1 融合分低于阈值 `0.35`，在检索阶段就已经拦截，连大模型都没有调用，既杜绝幻觉又省 token。

### 02:00 - 02:40｜展示评测与迭代故事（画面：终端 B 跑 `/api/eval/run` + `docs/iterations.md`）

- **画面操作**：
  - 切到终端 B 执行 `curl -s -X POST http://localhost:8080/api/eval/run`（或展示刚跑完的终端输出 JSON/日志表格），再切到 `docs/iterations.md` 的指标变化总览表。
- **口播词**：
  > 最后看这套 harness 最核心的评测闭环。调用 `/api/eval/run` 会把 52 道金标评测题全量走一遍刚才相同的线上链路，自动算出**检索命中率、引用准确率、拒答正确率**，并把结果落库等待人工标注**答案可用率**——当前实测命中、引用、拒答均达到 **100%**。
  > 在 `docs/iterations.md` 里我们记录了完整的控制变量迭代故事：阶段 6 把题库扩充到 52 题后，检索命中率一度掉到 95%。归因发现是关键词归一化软下限 `KeywordNormFloor=10.0` 太低，导致“调用/处理”这类中文泛词被放大成满分 1.0，把原本向量排第 1 的正确段落挤出了 Top 5。我们每次只改一个变量：先把软下限提到 `45.0`（命中率升到 97.5%），再把向量/关键词权重从 `0.6/0.4` 调到 `0.75/0.25`（命中率回到 100%），又补强了句级引用校验；甚至在迭代 5 尝试过更严格的 Prompt 反而造成误拒回退，我们直接按纪律回滚保留了迭代 4 基线。

### 02:40 - 03:00｜收尾（画面：回到项目目录或浏览器首页）

- **画面操作**：回到 Web 首页或终端仓库目录树。
- **口播词**：
  > 这个项目没有锁定任何特定模型或复杂框架，Go 标准工程加 MySQL 8 只有 `gin` 和 `mysql` 两个直接依赖。如果把 `corpus/` 换成任意真实的业务手册、API 文档或内部 Wiki，再配一套金标评测题，整套“切片、混合检索、硬引用护栏、四指标回归”的 harness 原样就能复用。演示到此结束，感谢观看。
