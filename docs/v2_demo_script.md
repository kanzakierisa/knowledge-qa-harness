# 3 分钟演示脚本（V3）

> 本文档整理了一套约 3 分钟的工作台全链路演示流程，面向当前 V3 界面与多项目演示沙箱编写，可边操作边介绍。

---

## 演前 1 分钟检查清单

1. **数据库状态**：确认已连接 `knowledge_qa_v3` 并运行过 `go run ./scripts/seed_demo_v2.go`，此时前端默认展示 **4 个可见内容消费演示空间**（共 11 篇文档，含 `.md / .docx / .xlsx / .pdf`）与 6 道 `feedback` 反馈回归题：
   - `【示例】公共规范库`（`shared`，2 篇 `.md`）
   - `【示例】内容活动运营`（`content-promo`，5 篇：`.docx` + `.xlsx` + `v1 deprecated.md` + `v2 active.md` + `.pdf`）
   - `【示例】红果短剧业务线`（`short-drama`，2 篇：`.md` + `.xlsx`）
   - `【示例】番茄小说创作者增长`（`novel-growth`，2 篇：`v1 deprecated.md` + `v2 active.docx`）
   - 注：原有 `go-gin`（39 篇 / 179 段）以及对抗盲测夹具 `project-alpha` / `project-beta` 均通过 `is_hidden=1` 默认隐藏保留在后台，仅用于 `base52` 与 `holdout` 离线量化回归，不干扰日常界面。
2. **启动服务**：
   ```powershell
   # 方式一（全配置直接启动）
   .\start.ps1
   # 或使用一键脚本 / 网页引导配置模式：
   .\scripts\quickstart.ps1 -SetupUI
   ```
3. **浏览器窗口**：打开 `http://localhost:8080`，确认页面极简干净（中栏顶部展示真实客观的「当前会话」统计栏：`引用准确率：-- · 反馈可用率：-- · 拒答：0 次`）。
4. **准备 1 个更新文件**：备好一份需要覆盖更新的 `promo-reward-and-approval-v2.md`（用于现场演示 `overwrite=true` 触发 Doc CI/CD 文档局部回归）。

---

## 分段脚本（00:00 - 03:00）

### 00:00 - 00:30｜开场、痛点引入与即插即用能力（画面：工作台首页 + 顶部引导配置态弹窗）

- **画面操作**：展示三栏工作台，点一下右上角「模型已就绪 / 模型配置」打开引导配置弹窗，稍停后关闭弹窗回到首页。
- **口播词**：
  > 各位评审好。团队文档分散在 Markdown、Word、Excel 和 PDF 里，直接把材料丢给通用大模型，往往会出现编造结论、跨项目规则混用，或者改完一篇规范悄悄破坏原有问答的情况。今天演示的是我用纯 Go 和 MySQL 8 手写的**可溯源知识问答与文档治理工作台（V3）**。我没有套用重型编排框架，而是自己搭建了一套确定性的 Agent Harness，把检索、引用校验、拒答护栏和回归评测全部管住。系统支持 `docker compose up` 一键启动，也支持通过 `--setup-ui` 在网页端临时填入模型密钥，配置只留在运行内存里，不会写入本地文件。

---

### 00:30 - 01:15｜多轮问答、废弃警告、`[n]` 原文 `<mark>` 高亮与任务列表管理（画面：「智能问答」页签）

- **画面操作**：
  1. 保持左侧默认「自动识别（防跨项目串台）」，依次在**同一会话**中提问：
     - 第 1 题：`新版活动发奖规则和端口配置有哪些注意事项？`
     - 等回答渲染完成后，指出 `[1]` `[2]` 引用标签以及 `已废弃` 旧版 v1 的黄色警示横幅，**点击正文 `[1]`**，展示右侧自动定位原文并在支撑句上渲染 `<mark class="evidence-hl">` 淡黄色荧光高亮。
     - 点击回答下方的 **`👍 准确`**，指出顶部「当前会话」统计实时更新，再点一下 **`📋 复制可信引用`** 展示一键复制团队可读出处的便捷体验。
     - （可选）同会话续问第 2 题：`冬季创作激励活动单篇基础奖励有哪些档位？`（命中 `.docx` 表格切片），展示左侧「任务」栏自动保存会话标题。
  2. 鼠标悬停到左侧任务项展示悬浮详情卡，点击 `...` 展示 **置顶 / 重命名 / 删除任务** 三项操作并点击 **置顶**，随后刷新一次浏览器页面展示任务与多轮对话、反馈状态全部从 MySQL 完整恢复。
- **口播词**：
  > 先看智能问答页，我在「自动识别」模式下提问内容活动的新版发奖规则和端口配置。系统命中了新版规范并在句末标出引用编号，同时弹出黄色横幅提醒旧版 v1 已经废弃。点击正文里的 `[1]`，右侧会自动定位原文段落，并用淡黄色 `<mark>` 精准高亮支撑这一句话的原句。点下「👍 准确」后，顶部「当前会话」只统计引用校验率、用户点赞反馈和真实拒答次数等客观指标，绝不伪造没有真值的虚假命中率。回答下方还能一键复制带完整文档出处的引用结论，方便直接发给团队；所有多轮对话任务也都会持久化保存在 MySQL 里，支持置顶和重命名管理。

---

### 01:15 - 01:55｜拒答护栏、跨项目歧义拦截与并排对照（画面：「智能问答」页签）

- **画面操作**：
  1. 输入语料外问题：`怎么做法式红酒炖牛肉？`
     - 展示系统秒出「文档中没有依据」拒答卡片（Top1 融合分 `< 0.35` 直接拦截，零 LLM 调用），顶部「当前会话」实时变成 `拒答：1 次`。
  2. 点击 **新对话**，输入跨项目冲突问题：`默认监听端口是多少？`
     - 展示系统弹出**跨项目歧义拦截**黄框，列出命中候选业务线（内容活动 `:8082`、红果短剧 `:8085`、番茄小说 `:8086`），点击 **`全部候选项目并排对照作答`**，直观展示各业务线各自独立检索的结果。
- **口播词**：
  > 如果接着问一个知识库里没有的问题，比如“怎么做法式红酒炖牛肉？”，检索融合分低于 `0.35` 会直接触发硬拒答，完全不调用大模型，既防幻觉又省去多余开销，同时自动沉淀进知识盲区雷达。而多项目并行团队最怕规范串台，比如直接问“默认监听端口是多少？”，系统检测到内容活动、红果短剧和番茄小说三条业务线都有相关规定，会先弹出歧义引导，不擅自替用户猜测；点击并排对照后，系统会按各个项目独立检索并分别列出 `8082`、`8085` 和 `8086` 端口，避免不同业务线混答。

---

### 01:55 - 02:30｜多格式治理与 Doc CI/CD 覆盖回归（画面：「资料库治理」页签）

- **画面操作**：
  1. 切换到顶部「**资料库治理**」，展示 4 个内容消费演示空间下的 `.md / .docx / .xlsx / .pdf` 多格式文档以及标注 `已废弃` 的 v1 版本替代链，点击 **预览** 核对切分好的文档段落。
  2. 切换到右侧上传抽屉，选择所属项目 `content-promo` 与文件 `promo-reward-and-approval-v2.md`，勾选 **强制覆盖重切（overwrite）** 点击上传；展开返回的 **Doc CI/CD 局部回归体检单**，展示受该文档影响的回归题自动重跑结果。
- **口播词**：
  > 切换到资料库治理页，界面默认聚焦 4 个内容消费演示空间，把 Markdown、Word、Excel 和 PDF 放在同一套索引体系下治理，原来的 Go 技术文档则默认在前端隐藏，只保留在后台用于回归评测。点击预览可以核对切分好的段落；如果我勾选「强制覆盖重切」热更新一篇规范，后端会自动匹配受影响的评测题并触发文档局部回归（也就是 Doc CI/CD），确认 2 题全部通过才算安全上线，而且回归跑批不会污染线上知识盲区库。

---

### 02:30 - 03:00｜盲区反馈闭环与量化基线收尾（画面：「盲区与反馈」页签）

- **画面操作**：
  1. 切换到「**盲区与反馈**」，点击一条待补充盲区展示最接近文档、负责人及「去补充文档」直达入口；再展示用户点踩的负面反馈在审阅后加入 `feedback` 活评测集的能力。
  2. 点击左侧 **`运行 feedback 活评测`**，展示 6 道反馈回归题全部通过，并指向中间滚动列表底部右对齐的 **`全部提问`** 真实线上统计。
- **口播词**：
  > 最后看「盲区与反馈」页，线上拒答的问题会自动沉淀为知识盲区，标出最接近的文档和负责人，方便团队直接补录；用户点踩的回答经审阅后也可以加入反馈评测集，作为持续积累的活评测集。点击运行反馈集回归，6 题全部通过，底部同时汇总全库的真实线上统计，与离线回归严密隔离。在离线量化评测上，整套系统在 52 题基准集（`base52`）和 39 题对抗盲测集（`holdout`）上均守住了 100% 的拒答底线，哪怕是混入真实 API 名称的陷阱题（`near_miss_refusal`，13/13）也不会乱答。以上就是我的演示，感谢观看。
