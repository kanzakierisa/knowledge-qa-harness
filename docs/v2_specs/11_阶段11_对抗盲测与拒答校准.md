# 阶段 11：对抗盲测集建设与拒答/召回防过拟合校准

> 前置：阶段 10 验收全部通过。先读 `00_V2总体规格.md`。
> 本阶段目标：针对你关注的“模型误拒 vs 过拟合风险”，**先建一面“照妖镜”（独立对抗盲测集），再用严格的单变量控制实验校准策略**，不碰原有 52 题的干净基线。

---

## 目标

1. 建成独立于 `base52` 的 **35+ 题对抗盲测集（`question_set='holdout'`）**，其中专门包含高分陷阱拒答题。
2. 通过单变量实验验证**多实体覆盖召回**、**可选 Rerank**、以及**拒答复核/两阶段验证**到底有没有泛化收益；凡是拉低高分陷阱拒答率或退化 `base52` 的改动，坚决回滚并记录。

## 任务清单

### 1. 扩建独立对抗盲测集（`scripts/seed_holdout.go`）
编写与 `seed_eval.go` 同风格（`//go:build ignore`、用 `(filename, heading_path, snippet)` 自动解析真实 `gold_chunk_id`、支持 `-review` 审阅）的脚本 `scripts/seed_holdout.go`，写入 `eval_questions` 时标记 `question_set = 'holdout'`，**总题数 ≥ 35 题**，必须覆盖以下 4 类：

1. **换问法 / 隐含前提纠偏可作答题（≥ 10 题）**：
   - 选不同于原 `q_id=33/37` 的新知识点，测试跨问法/纠偏作答泛化能力（例如：`gin.New()` 与 `gin.Default()` 区别的反向问法、JSON 数字解到 `map` 后为什么不能直接当 `int` 用、`c.BindJSON` 出错后继续写响应会发生什么等）。
2. **“高分陷阱”边界拒答题（≥ 12 题，`should_refuse = 1` — 反过拟合核心！）**：
   - **刻意在问题中使用语料真实存在的精确函数名/API 词**，但询问语料并未收录的参数、底层实现或特性，确保其检索分高达 `0.50~0.75`，专门检验系统会不会“因为分数高就误放行编造”。
   - 示例类型：`r.Run()` 原生支持直接传入 HTTPS 证书路径开启 TLS 吗？、`c.ShouldBindJSON` 内部默认使用标准库还是 `goccy/go-json`？、`filepath.Join` 会自动校验目标路径在磁盘是否存在吗？、`sync.WaitGroup` 可以按值传参进子 goroutine 吗？、`regexp.MustCompile` 支持 PCRE 环视语法吗？
3. **多实体跨段落对比题（≥ 6 题）**：
   - 例如：`c.Query` 与 `c.Param` 的区别、`errors.Is` 与 `errors.As` 各自解决什么问题、值接收者与指针接收者在修改字段时的差异（跨多个独立切片，测试多实体同时召回进 Top 5）。
4. **多项目与文档治理测试题（≥ 7 题）**：
   - 绑定特定 `project_slug` 验证同词跨项目隔离与废弃文档场景。

*(注：执行 `scripts/seed_holdout.go` 后，人工审阅一遍全部题目与 `gold_chunk_id` 确保无错题或歧义题；`POST /api/eval/run?set=holdout` 独立跑批，绝不混入 `base52`。)*

### 2. 控制变量候选实验（写入 `docs/v2_iterations.md`）
每次**只改 1 个变量**，同时在 `base52`（52 题）与 `holdout`（35+ 题）上全量评测并人工标注 `usable`：

- **实验 1：检索层“多标识符覆盖保底”（通用无参数污染，强烈推荐先做）**
  - 问题背景：类似 `c.Query 和 c.Param 的区别是什么`，Top 5 可能全被 `c.Query` 占满而漏掉 `c.Param`。
  - 通用代码实现（不针对任何具体词写死）：
    1. 用 `retrieve` 的标识符切词规则提取问句中长度 `>= 2` 的英文/代码精确词（或复合词如 `c.param`、`errors.as`）；
    2. 在原始融合排序 Top 15 中，若发现问句含多个高区分度标识符（IDF 高于均值），而 Top 5 完全没有包含某个标识符，则从 Top 6~15 中取含该标识符且融合分最高的一段（且 `Final >= refuseThreshold`），替换进 Top 5 末尾（仍保持总数 `<= 5`）。
  - 验证目标：观察多实体对比题命中率与回答率是否上升，且高分陷阱题拒答率不跌。

- **实验 2（可选，若配置了 `RERANK_BASE_URL`）：Cross-Encoder 重排精筛**
  - 新增 `retrieve/rerank.go`：先用向量+BM25 取候选 Top 15，再调用 Rerank API 重排后取 Top 5。
  - 若未配置 `RERANK_BASE_URL` 则自动回落纯融合 Top 5，保持零外部依赖也能跑。
  - 验证目标：观察 Rerank 是否压低“高分陷阱拒答题”的得分、同时提升语义改写题进入 Top 1 的比例。

- **实验 3（审慎试点，严格执行回滚红线）：两阶段“宽松草稿 + 独立事实验证器” vs “高置信拒答通用复核”**
  - **绝对禁止**用纯 Go 字符串匹配去推翻 LLM 拒答，也**绝对禁止**针对 `filepath.Join` / `regexp.MustCompile` 写特殊 Prompt！
  - 可测试通用机制：
    - 当 `top1.Final >= 0.55` 且模型首次输出拒答时，不直接改判答案，而是发起一次通用二次核查（要求模型逐条对照资料检查是否存在“通过行为描述/异常/机制优势间接回答了问题”的情况，若确无直接或等价推导依据仍必须输出 `文档中没有依据`）；
    - 且只要二次核查产出了非拒答草稿，必须再过一遍独立的 **Factuality Verifier 调用**（把问题 + 草稿 + 引用原文喂给独立验证 Prompt，严格检查草稿中每一句是否被引用原文完全蕴含、有无擅自外推条件），验证不通过则照旧兜底拒答！
  - **回滚红线**：只要在 `holdout` 的 **高分陷阱拒答题** 上出现哪怕 **1 例幻觉放行（拒答率 < 100%）**，或者 `base52` 任一指标退化 > 2%，**立即撤销实验 3 并记录“负向实验，已回滚”**！

### 3. `/api/eval/run` 扩展与实验归档
- `POST /api/eval/run` 支持 `?set=base52`（默认）、`?set=holdout`、`?set=feedback`、`?set=all`。
- `eval` 报告 JSON 增加按 `category` 分组的小计（特别清晰打印出 `near_miss_refusal` 高分陷阱拒答题的单独命中与拒答通过率）。
- 完整记录所有实验数据到 `docs/v2_iterations.md`（延续 `docs/iterations.md` 格式：改动、原因、基线 vs 实验指标表、人工抽核结论、保留或回滚）。

## 验收（全部通过才算完成）

```bash
# 1. 导入 holdout 盲测集并审阅
go run ./scripts/seed_holdout.go -review
go run ./scripts/seed_holdout.go

# 2. 分别跑通 base52 与 holdout 独立评测并完成人工 usable 标注
curl -X POST "http://localhost:8080/api/eval/run?set=base52"
curl -X POST "http://localhost:8080/api/eval/run?set=holdout"

# 3. 核对防过拟合核心指标：
#   - base52 四项指标不低于 V1 阶段 8 基线（命中 100%、引用 100%、可用 100%、拒答 100%）
#   - holdout 中高分陷阱拒答题（near_miss_refusal）拒答正确率 == 100%
#   - 多实体对比题（如 c.Query vs c.Param）命中率有明确提升且有数据记录

# 4. 代码校验与单测
go vet ./... && go test -count=1 ./...
```

## 禁止事项

- 禁止修改 `base52` 原 52 道题目文本或 `gold_answer` 来刷指标。
- 禁止把实验 3 中引发幻觉的策略硬留在主干——宁可保持保守误拒，绝不放过幻觉。
- 禁止绕过 `ValidateCitations` 句级硬校验。
