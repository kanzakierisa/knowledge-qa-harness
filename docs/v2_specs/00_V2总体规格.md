# 知识问答 Agent Harness — V2 总体规格（竞赛完善版）

> **这份文档是 V2 阶段的“宪法”。** 每个新会话开始执行阶段 9～13 时，都必须先读本文档，再读对应阶段的任务书。
> 本规格在 V1（`stage8-delivered` 标签）基础上扩展；**任何阶段任务书与本文档冲突时，以本文档为准。**

## 1. 项目定位与赛题对齐

本项目针对字节跳动「巨量引擎｜新生意创造者·AI挑战赛」赛题 5 —— **《为知识密集型、多项目并行团队构建知识问答 Agent Harness》**（面向内容消费 AI 团队：AI 产品 / AI 产运方向）。

在保留 V1“**可评测、可溯源、无据拒答、控制变量迭代**”核心底座的前提下，V2 聚焦解决真实多项目团队的四大痛点：

1. **多项目不串台**：项目空间物理/逻辑隔离 + 全局提问同名冲突主动澄清护栏。
2. **非标资料也能进**：支持 `.md` / `.txt` / `.docx` / `.xlsx` / `.pdf`（及可选图片/扫描件）热上传并自动标准化为结构化 Markdown 切片，支持单篇增删改与文档权威度/废弃态治理。
3. **不靠过拟合降误拒**：保留原 52 题基线不变，独立构建“高分陷阱 + 前提纠偏 + 多实体对比”对抗盲测集，通过多实体召回/重排/事实验证校准拒答边界。
4. **知识与评测自生长闭环**：拒答自动沉淀“团队知识盲区雷达”、答案句级荧光溯源、用户点踩一键转正金标题、更新文档触发关联金标局部回归（Doc CI/CD）。

### 这不是什么（红线不许破）

- ❌ 不是黑盒多智能体漫游框架。禁止引入 LangChain、LlamaIndex、AutoGen 等编排框架，禁止无上限 ReAct 循环。
- ❌ 不靠硬编码某个题目关键字或“强行覆盖拒答”刷指标。
- ❌ 不破坏 V1 基线：`master` 分支、`stage8-delivered` 标签、`migrations/001_init.sql` 及原 MySQL `knowledge_qa` 库均保持不动；V2 全程在 `feat/v2-harness` 分支与独立数据库 `knowledge_qa_v2` 上演进。

## 2. 技术栈与 V2 依赖边界

| 项 | V2 选型与边界 | 说明 |
|---|---|---|
| 语言 | Go（1.22+） | 延续 V1 |
| HTTP 框架 | Gin（`github.com/gin-gonic/gin`） | 延续 V1 |
| 数据库 | MySQL 8（`github.com/go-sql-driver/mysql`） | 在 `001_init.sql` 之上增量执行 `migrations/002_v2_schema.sql` |
| 向量与关键词计算 | Go 代码手写余弦相似度 + BM25（可加内存缓存） | 2,000 段以内内存计算毫秒级；数据变更时失效刷新 |
| 文档解析白名单（按需引入） | 纯 Go 轻量解析库白名单：<br>- `.docx`：`github.com/gomutex/godocx`<br>- `.xlsx`：`github.com/qax-os/excelize/v2`<br>- `.pdf`：`github.com/pdfcpu/pdfcpu` 或 `github.com/ledongthuc/pdf`（二选一，选前在阶段 9 确认）<br>禁止引入 CGO 依赖或重型框架 | 如需接入外部轻量解析 CLI（如 `markitdown` / `pandoc`）或 VLM OCR，必须通过独立 `Converter` 接口与可选环境变量开关接入，保证默认纯 Go 模式可编译运行 |
| LLM / Embedding / 可选 Rerank / 可选 VLM | OpenAI 兼容 HTTP API，**全部走环境变量配置** | 代码里**禁止硬编码任何 Key、地址、模型名** |
| 前端 | 原生 HTML / CSS / JS，单页面或轻量多标签页，**禁止前端框架与外链 CDN** | `//go:embed` 内嵌打包，确保离线/跨平台一致 |

## 3. 配置规范（严格向后兼容 V1）

### 3.1 必需环境变量（5 项不变）

```text
LLM_BASE_URL      # 对话 OpenAI 兼容 API 地址，如 https://api.deepseek.com/v1
LLM_API_KEY       # 对话 API key
LLM_CHAT_MODEL    # 对话模型名，如 deepseek-chat
LLM_EMBED_MODEL   # embedding 模型名，如 text-embedding-v3
MYSQL_DSN         # V2 建议指向独立库 knowledge_qa_v2，如 root:pwd@tcp(127.0.0.1:3306)/knowledge_qa_v2?charset=utf8mb4&parseTime=true
```

**强约束**：常规启动 `config.Load()` 仍必须校验上述 5 个变量全部非空，缺任何一个直接报错退出并提示缺哪个（确保阶段 1 审计单测 `TestAuditStage1RequiredVariables` 永远通过）。

### 3.2 V2 可选环境变量

```text
EMBED_BASE_URL    # 独立 Embedding 平台地址（缺省回落 LLM_BASE_URL）
EMBED_API_KEY     # 独立 Embedding API Key（缺省回落 LLM_API_KEY）
HTTP_ADDR         # 监听地址，默认 :8080
RERANK_BASE_URL   # 可选：重排 API 地址（阶段 11 实验启用，未配则跳过重排）
RERANK_API_KEY    # 可选：重排 API Key（缺省回落 EMBED_API_KEY / LLM_API_KEY）
RERANK_MODEL      # 可选：重排模型名，如 gte-rerank / bge-reranker-v2-m3
LLM_VLM_MODEL     # 可选：扫描件 PDF / 图片转 Markdown 的多模态模型名（未配则在遇扫描件时明确提示报错，不乱码入库）
CONVERT_ENGINE    # 可选：native（默认纯 Go） | markitdown（调用本地 markitdown CLI）
```

> 阶段 13 若提供 Web 端首次引导配置能力，只能通过显式标志（如 `--setup-ui`）或独立的配置覆盖机制启用，不得破坏默认 `config.Load()` 的必填报错契约；`.env.example` 必须同步列出 V2 可选变量注释且不填真实值。

## 4. V2 数据库增量迁移契约（`migrations/002_v2_schema.sql`）

> 铁律：**禁止修改 `migrations/001_init.sql` 原有 4 张表定义中已有列的类型与语义**；所有 V2 变更通过幂等脚本 `migrations/002_v2_schema.sql` 追加。

```sql
-- 1. 项目空间表（含默认 shared 公共域与默认项目）
CREATE TABLE IF NOT EXISTS projects (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  slug VARCHAR(64) NOT NULL UNIQUE,
  name VARCHAR(120) NOT NULL,
  description VARCHAR(500) NOT NULL DEFAULT '',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

INSERT IGNORE INTO projects (id, slug, name, description) VALUES
  (1, 'shared', '公共规范库', '跨项目共享的团队通用规范与基础文档'),
  (2, 'go-gin', 'Go/Gin 技术文档', 'V1 原始 Go 与 Gin 官方文档语料');

-- 2. documents 扩充文档治理与项目归属字段
ALTER TABLE documents
  ADD COLUMN project_id BIGINT NOT NULL DEFAULT 2,
  ADD COLUMN source_type VARCHAR(32) NOT NULL DEFAULT 'md',
  ADD COLUMN content_hash CHAR(64) NOT NULL DEFAULT '',
  ADD COLUMN doc_level ENUM('spec', 'rfc', 'note') NOT NULL DEFAULT 'spec',
  ADD COLUMN status ENUM('active', 'deprecated') NOT NULL DEFAULT 'active',
  ADD COLUMN replaced_by_doc_id BIGINT NULL,
  ADD COLUMN owner VARCHAR(100) NOT NULL DEFAULT '',
  ADD COLUMN updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  ADD CONSTRAINT fk_documents_project FOREIGN KEY (project_id) REFERENCES projects(id);

-- 3. eval_questions 扩充评测集分组与来源文档绑定（原 52 题默认归为 base52）
ALTER TABLE eval_questions
  ADD COLUMN project_slug VARCHAR(64) NOT NULL DEFAULT '',
  ADD COLUMN question_set VARCHAR(32) NOT NULL DEFAULT 'base52',
  ADD COLUMN source_doc_id BIGINT NULL,
  ADD COLUMN category VARCHAR(64) NOT NULL DEFAULT '';

-- 4. 团队知识盲区雷达（仅记录真实问答拒答，评测跑批不写入）
CREATE TABLE IF NOT EXISTS knowledge_gaps (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  project_slug VARCHAR(64) NOT NULL DEFAULT 'auto',
  question TEXT NOT NULL,
  normalized_key VARCHAR(255) NOT NULL,
  refuse_reason VARCHAR(64) NOT NULL,          -- threshold | model_refusal | citation_fail
  top1_final DOUBLE NOT NULL DEFAULT 0,
  nearest_chunk_id BIGINT NULL,
  nearest_heading VARCHAR(500) NOT NULL DEFAULT '',
  hit_count INT NOT NULL DEFAULT 1,
  status ENUM('open', 'resolved', 'ignored') NOT NULL DEFAULT 'open',
  last_asked_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_gap_proj_key (project_slug, normalized_key)
);

-- 5. 用户回答反馈与活评测集待审队列
CREATE TABLE IF NOT EXISTS eval_feedback (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  project_slug VARCHAR(64) NOT NULL DEFAULT 'auto',
  question TEXT NOT NULL,
  retrieved_chunk_ids VARCHAR(500) NOT NULL DEFAULT '[]',
  answer TEXT NOT NULL,
  refused TINYINT(1) NOT NULL DEFAULT 0,
  vote ENUM('up', 'down') NOT NULL,
  comment VARCHAR(500) NOT NULL DEFAULT '',
  promoted_question_id BIGINT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

*(注：执行 `002_v2_schema.sql` 时若 MySQL 8 不支持 `ADD COLUMN IF NOT EXISTS`，可用存储过程条件判断或明确只对全新执行过 `001_init.sql` 的 `knowledge_qa_v2` 执行一次，并在脚本头部注释说明。)*

## 6. V2 评测指标体系

| 指标 | 定义 | 口径要求 |
|---|---|---|
| 检索命中率 | 可作答题中 `gold_chunk` 进入 Top 5 的比例 | `base52` 与 `holdout` 分别统计，互不混算 |
| 引用准确率 | 非拒答回答中句级引用全部合法的比例 | 复用阶段 4/6 的 `ValidateCitations` |
| 答案可用率 | 人工标注 `usable=true` 的比例 | **永不自动判分**；未标注返回 `null` |
| 拒答正确率 | 应拒答题实际拒答的比例 | **必须单独列出 `holdout` 中“高分陷阱拒答题”的拒答正确率**，作为防过拟合红线 |
| 误拒率（观测） | 可作答题却被拒答的比例 | `false_refusal_count / answerable_count` |
| 隔离与歧义准确率（阶段 10+） | 跨项目隔离/歧义测试集通过率 | 指定项目 0 串台、冲突提问 100% 识别歧义 |

**控制变量红线**：任何一次改动（切片、排序权重、Rerank、两阶段校准）后必须同时重跑 `base52` 和 `holdout`，结果写入 `docs/v2_iterations.md`；凡导致 `holdout` 高分陷阱拒答出现任何退化、或 `base52` 任一指标下降超 2 个百分点，必须立即回滚并记录原因。

## 7. V2 HTTP 接口契约（严格向后兼容 V1）

### V1 原有接口（无新参数时行为 100% 兼容）

| 方法 | 路径 | 兼容与扩展说明 |
|---|---|---|
| `POST` | `/api/ask` | 入参新增可选 `"project_slug": ""`（空或 `"auto"` 为自动路由）与 `"compare": false`；返回新增可选 `"project_resolved"`、`"ambiguity"`、`"warnings"`（引用废弃文档时非空） |
| `GET` | `/api/chunks` | 保留返回 `{"total": N}`，可选传 `?project_slug=...` 过滤 |
| `POST` | `/api/eval/run` | 默认只跑 `question_set='base52'`（保证兼容阶段 5/6）；支持 `?set=base52\|holdout\|feedback\|all` |
| `POST` | `/api/eval/mark` | 与 V1 完全一致 |

### V2 新增接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` / `POST` | `/api/projects` | 查询项目列表 / 创建新项目空间 |
| `GET` | `/api/documents` | 列出文档（支持 `?project_slug=&status=`），含切片数、状态、负责人 |
| `POST` | `/api/documents/upload` | 多格式热入库（`multipart/form-data` 或 JSON 文本，支持 `overwrite`、自动 `Doc CI/CD` 局部回归摘要） |
| `PATCH` | `/api/documents/:id` | 修改文档 `status`（`active`/`deprecated`）、`doc_level`、`owner`、`replaced_by_doc_id` |
| `DELETE` | `/api/documents/:id` | 事务删除文档及其 `chunks`，返回关联金标影响提示 |
| `GET` / `PATCH` | `/api/gaps` / `/api/gaps/:id` | 查看团队知识盲区列表（按 `hit_count` 降序）与更新状态（`resolved`/`ignored`） |
| `POST` / `GET` | `/api/feedback` | 提交 `👍/👎` 反馈 / 查看待审负面反馈 |
| `POST` | `/api/feedback/:id/promote` | 将负面反馈审阅转正为 `eval_questions`（`question_set='feedback'`） |

## 9. 执行纪律（所有 V2 会话必须遵守）

1. **阶段隔离**：一个会话只做 1 个阶段，开始前先确认当前处于 `feat/v2-harness` 分支、连接的是 `knowledge_qa_v2` 库。
2. **先测试后过关**：每个阶段结尾必须跑通本阶段全部验收命令，并跑一次 `go vet ./...` 与 `go test -count=1 ./...` 回归，全部通过才准进入下一阶段。
3. **禁止静默兜底掩盖错误**：解析失败（如加密 PDF、无文字层且未配 VLM 的扫描件）必须返回明确中文错误信息；不得悄悄吞错入库空串。
4. **全程保持零凭据入库**：任何脚本、Docker 配置、示例文件、文档均不得包含真实 Key 或密码。
