# 阶段 12：知识盲区雷达、句级原文高亮与活评测闭环（Doc CI/CD）

> 前置：阶段 11 验收全部通过。先读 `00_V2总体规格.md`。
> 本阶段目标：紧扣内容消费 AI 团队对“**团队协作效率、价值可感知、反馈极短**”的要求，把单向问答机器升级为会自我发现文档缺口、越用越准的自生长 Harness 闭环。

---

## 目标

实现四大团队协作闭环能力：
1. **知识盲区雷达**：线上拒答自动归档统计，告诉团队“大家常问但文档缺失什么”。
2. **证据句荧光高亮**：点击 `[n]` 后，在来源卡片内部精准标出支撑结论的那一两句话。
3. **线上反馈一键转金标**：用户点 `👎` 一键进入待审队列，确认后直通回归集。
4. **文档热更新局部回归（Doc CI/CD）**：更新单篇文档后自动重跑受影响题目，立即报告是否冲垮旧问答。

## 任务清单

### 1. 团队知识盲区雷达（`knowledge_gaps`）
- **写入规则（必须严格隔离评测跑批！）**：
  - 在 `Handler.answerQuestion` 增加内部标志或参数（如 `recordGap bool`）：
    - 线上 `POST /api/ask` 调用时 `recordGap = true`；
    - `/api/eval/run` 与 Doc CI/CD 内部评测调用时 `recordGap = false`，**严禁跑评测集把几十条测试题灌进团队线上盲区榜**！
  - 当触发阈值拒答（`refuse_reason = "threshold"`）、模型自拒答（`"model_refusal"`）或引用校验重试失败兜底拒答（`"citation_fail"`）时，写入或累加 `knowledge_gaps`：
    - `normalized_key`：对问句 `TrimSpace` + 小写 + 去除末尾中文/英文标点（`？?。！!`）+ 连续空白折叠后截取/SHA-256，确保同一问法多次被问自动 `hit_count = hit_count + 1` 并刷新 `last_asked_at` 与 `top1_final`；
    - 记录最接近但未达标或未使用的 `nearest_chunk_id` 与 `nearest_heading`，方便负责人知道“大概应该补在哪篇文档下”。
- **HTTP 接口**：
  - `GET /api/gaps`：支持 `?project_slug=&status=open`，按 `hit_count DESC, last_asked_at DESC` 排序，附带近似文档标题与负责人建议。
  - `PATCH /api/gaps/:id`：将盲区标记为 `resolved`（文档已补充）或 `ignored`。

### 2. 来源卡片“证据句级荧光高亮”（`static/index.html`）
- 目标：不仅跳到对应来源卡片，还要让用户 1 秒看清原文中哪一句支撑了模型答案。
- **纯前端无依赖实现规范（严禁 XSS！）**：
  1. 提取答案正文（剥离代码块）中包含 `[n]` 的句子文本 `claimText`；
  2. 将来源卡片 `[n]` 的 `item.content` 按句末标点/换行切分为候选原句（跳过代码围栏内语法块或保持整块判断）；
  3. 用轻量词面重叠算法（如去除停用字后的 2-gram + 英文标识符交集率，重叠率达到阈值如 `>= 0.35` 且命中字符数 `>= 4`，取卡片内得分最高的前 1~2 句）定位核心支撑句；
  4. 渲染时**严禁使用 `innerHTML` 拼接原文本**！必须通过 `document.createElement('mark')`（带 `.evidence-hl` 淡黄色背景）+ `document.createTextNode(...)` 安全拼装 DOM；点击其他 `[m]` 时自动切换高亮对应卡片与对应句子。

### 3. 用户 `👍 / 👎` 反馈与一键转正活评测集
- 回答卡片底部新增极简操作行：`这道回答有帮助吗？` + `[👍 准确]` + `[👎 有问题/漏答]`（点 `👎` 可附带可选简短备注输入框，如“文档明明写了在第 3 节”）。
- **HTTP 接口**：
  - `POST /api/feedback`：保存 `(project_slug, question, retrieved_chunk_ids, answer, refused, vote, comment)` 到 `eval_feedback`。
  - `GET /api/feedback`：按 `vote='down'` 和未转正优先列出反馈队列。
  - `POST /api/feedback/:id/promote`：入参 `{gold_answer, should_refuse, gold_chunk_id, category}`（若 `should_refuse=false` 校验 `gold_chunk_id` 存在），在事务内写入 `eval_questions`（`question_set = 'feedback'`）并回填 `eval_feedback.promoted_question_id`，立即成为后续评测集一员！

### 4. 文档热更新触发局部回归（Doc CI/CD）
- 当调用 `POST /api/documents/upload` 并覆盖更新一篇已有文档（`overwrite=true` 或同项目同名新版本替换）时：
  1. 先查出所有 `eval_questions` 中满足 `source_doc_id = 该文档ID`（或 `gold_chunk_id` 原属于该文档旧切片的题——注意要在删旧 `chunks` **之前**查出关联题列表及通过 `heading_path` 重新绑定新切片，或提示需重绑！）；
  2. 新切片入库完成后，自动以 `recordGap=false` 重跑这批关联金标题（若原题定位锚点仍在，尽可能自动重解析新 `gold_chunk_id`；无法自动重解析的单独标记 `needs_review`）；
  3. 在上传响应 JSON 中附带 `regression_summary`：
     `{"checked": N, "passed": M, "refused_unexpectedly": K, "needs_review": R, "details": [...]}`；
  4. 前端上传覆盖成功提示框直接渲染这次“局部回归体检单”，让改文档的人一眼知道有没有改坏原有问答。

### 5. 前端工作台完善（`static/index.html`）
- 顶部页签扩充为三个清爽板块（依然零框架、零 CDN、移动端自适应）：
  - **「智能问答」**：项目选择 + 提问 + 歧义澄清 + 废弃警告 + 荧光高亮溯源 + `👍/👎` 反馈；
  - **「资料库治理」**：多格式上传（含 Doc CI/CD 回归摘要展示）、文档列表、废弃态切换与替代关系设置、删除；
  - **「盲区与反馈」**：团队高频未覆盖问题 Top N（带一键“去补充文档”跳转和“已解决”按钮） + 负面反馈待审转正列表。
