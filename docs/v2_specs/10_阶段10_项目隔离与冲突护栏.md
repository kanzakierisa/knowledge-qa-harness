# 阶段 10：多项目硬隔离、跨项目歧义拦截与文档治理护栏

> 前置：阶段 9 验收全部通过。先读 `00_V2总体规格.md`。
> 本阶段目标：真正体现**“多项目并行团队”**和**“文档治理”**——绝不把 B 项目的规范串台答进 A 项目；全局提问撞车时主动澄清；引用已废弃旧文档时强制弹窗警告。

---

## 目标

实现三项多项目团队专属护栏：
1. **空间硬隔离**：指定项目时，检索物理过滤为 `目标项目 + shared`。
2. **跨项目歧义拦截**：全局未指定项目提问且多项目同现高分竞争时，不强行混答，而是输出结构化歧义引导。
3. **权威度与废弃态治理**：正式规范优先于零散纪要；一旦答案实际引用了 `deprecated` 文档，必须返回明确黄色警示与替代文档引导。

## 任务清单

### 1. 检索域过滤与文档治理加权（`retrieve/merge.go`）
- 扩展检索入参或过滤条件（保持原有 `Merge(...)` 签名可用，新增 `MergeWithOptions` 或在 `Chunk` 结构携带 `ProjectID`、`ProjectSlug`、`DocID`、`DocTitle`、`DocLevel`、`DocStatus`、`ReplacedByDocID`、`DocOwner`）：
  - 当 `project_slug` 非空且不等于 `"auto"` 时：**在检索阶段直接过滤**，只保留 `ProjectSlug == target || ProjectSlug == "shared"` 的切片参与打分。
  - 若目标项目（含 `shared`）完全无切片：直接返回空，明确提示当前项目暂无资料（不跨项目偷拿其他项目切片）。
- **文档治理微调系数**（全部写成带注释的清晰常量，方便阶段 11 控制变量调优）：
  - `DocLevel` 权重倍率（建议初始值：`spec = 1.00`，`rfc = 0.96`，`note = 0.92`）；
  - `DocStatus` 权重倍率（建议初始值：`active = 1.00`，`deprecated = 0.78`——既把现行有效文档排前面，又保证当新文档缺失、只有旧文档可答时仍能召回并触发下一条废弃警示）。
  - 注意：`Final = (VectorWeight*vs + KeywordWeight*kw) * levelFactor * statusFactor`，保证不突破 `0~1` 范围，且原有纯 `go-gin`（全为 `spec + active`）行为倍率均为 `1.00`，**完全兼容 V1 评测基线**。

### 2. 跨项目歧义拦截护栏（`api/handler.go`）
当 `project_slug == ""` 或 `"auto"`（全局视角提问）时，在融合检索得到排序结果后、调用 LLM 之前增加歧义检测函数 `detectCrossProjectAmbiguity`：
- **精确判定规则**（避免误拦）：
  1. 取所有 `Final >= refuseThreshold` 的候选切片（看 Top 8 候选）；
  2. 记录其中**非 `shared` 项目**（每个项目取其最高得分 `projTopScore`）；
  3. 仅当满足以下全部条件时触发歧义拦截：
     - 存在 **≥ 2 个不同的非 `shared` 项目**满足 `projTopScore >= refuseThreshold`；
     - 第 2 名项目的最高分与全场 Top1 分差在竞争窗口内（例如 `top1.Final - secondProjTopScore <= 0.08`）。
- **拦截后的返回结构**（若请求未传 `"compare": true`）：
  - **不调用 LLM 生成混杂答案**，直接返回：
    ```json
    {
      "answer": "检测到多个并行项目均包含与该问题相关的规范，请先确认您要查询的具体项目：",
      "citations": [...],
      "refused": false,
      "retried": false,
      "project_resolved": "ambiguous",
      "ambiguity": {
        "detected": true,
        "candidates": [
          {"project_slug": "project-a", "project_name": "项目 A", "top_score": 0.68, "top_heading": "..."},
          {"project_slug": "project-b", "project_name": "项目 B", "top_score": 0.65, "top_heading": "..."}
        ]
      }
    }
    ```
  - 当只有 1 个非 `shared` 项目进入竞争窗口时：自动把 `project_resolved` 设为该 `project_slug`，**过滤掉其他非 `shared` 项目的零散干扰切片后**再取 Top 5 交给 LLM！
  - 可选加分：若请求显式传入 `"compare": true`，可针对每个候选项目分别走一次单项目问答，返回 `comparisons: [{project_slug, answer, citations}, ...]` 供并排对照。

### 3. 废弃文档（`deprecated`）硬警告与 Prompt 协同（`generate/` + `api/`）
- **Prompt 透明标注**：在拼接 `[1]`..`[5]` 给 LLM 时，对来源元信息做简洁标头（如 `[1]（项目: project-a | 类型: spec | 状态: active）正文...`；若为废弃文档则标 `状态: deprecated（已废弃）`），提醒模型不要把过期纪要当成最新生效规范，同时保持对阶段 4 句级 `[n]` 校验的 100% 兼容。
- **代码层结构化警告输出（不依赖模型自觉）**：
  - 生成答案并校验通过后，提取正文中实际引用到的编号 `[n]`（沿用 `extractCitedNumbers` 逻辑，剥离代码段）；
  - 若任一被引用段落所属文档 `status == "deprecated"`，在 `askResponse` 填充 `warnings` 数组：
    ```json
    "warnings": [
      {
        "type": "deprecated_doc",
        "chunk_n": 1,
        "document_title": "旧版激励活动规则 v1",
        "owner": "李四",
        "replaced_by_doc_id": 45,
        "replaced_by_title": "新版激励活动规则 v2",
        "message": "引用来源 [1] 来自已废弃文档《旧版激励活动规则 v1》（负责人：李四），建议查阅替代文档《新版激励活动规则 v2》。"
      }
    ]
    ```
  - 并在 `citation` 结构体补充 `project_slug`、`doc_status`、`doc_level`、`owner` 字段。

### 4. Web 界面升级（`static/index.html`）
- 在提问输入框上方增加**项目空间切换条**：默认选项为 `自动识别（防跨项目串台）`，并动态从 `GET /api/projects` 渲染各项目芯片/下拉选项。
- 收到 `ambiguity.detected == true` 时：展示清晰的选择引导卡片，**每个候选项目渲染成可点击按钮**，点击后自动锁定该项目并立即重发该问题！
- 收到 `warnings` 非空时：在答案卡片顶部渲染醒目黄色警告横幅（含废弃原因、负责人与替代文档说明）。
- 每张来源卡片标题行增加极简标签：所属项目名、文档类型（规范/RFC/纪要）、`已废弃` 灰红标记（若有）。
