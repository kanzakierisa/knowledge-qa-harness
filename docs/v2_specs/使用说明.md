## 推荐新会话开场模板（每阶段一个新会话最稳）

每次打开新会话时，发送以下内容（把 `[X]` 替换成当前要做的阶段，例如 `09_阶段9_多项目与多格式入库.md`）：

```text
请先完整阅读以下文档和当前代码仓库（D:\knowledge-qa）：
1. D:\knowledge-qa\docs\v2_specs\00_V2总体规格.md
2. D:\knowledge-qa\docs\v2_specs\[X]
3. D:\knowledge-qa\docs\iterations.md（了解 V1 的控制变量风格与已验证参数）

前置确认：
- 确认当前处于 feat/v2-harness 分支，禁止修改 master 分支与 stage8-delivered 标签，禁止修改原 MySQL knowledge_qa 库与 D:\knowledge-qa_2 内任何文件。
- V2 使用独立 MySQL 数据库 knowledge_qa_v2（通过环境变量或本地未入库的启动脚本提供 API Key 与 DSN 做实测，严禁把真实凭据写入仓库追踪文件）。
- 严格遵循任务书范围与《V2总体规格》红线，若遇到技术选型或细节不明确，先向我确认再动手。
- 本阶段全部实现与验收通过后，输出：改动文件列表、运行方式、验收结果（逐项标明是否通过）。
```

## 你需要亲手把关的关键节点

1. **阶段 9（格式解析库选型确认）**：确认 `.pdf` 与 `.docx` 的纯 Go 库及是否开启可选 VLM OCR 兜底。
2. **阶段 11（对抗盲测题审阅 & 回滚把关）**：跑 `go run ./scripts/seed_holdout.go -review` 审阅 35+ 道盲测题是否无歧义；严格盯住高分陷阱拒答题不能为了降误拒而放水产生幻觉。
3. **阶段 13（11.25 前竞赛打包）**：用新录屏脚本录制 3 分钟演示视频，上传 GitHub（确保历史零 Key）并连同简历在 `11.25` 前提交报名。
