# 阶段 9：多项目底座、多格式转 Markdown 与动态资料库

> 前置：`stage8-delivered` 已备份，当前处于 `feat/v2-harness` 分支。先读 `00_V2总体规格.md`。
> 本阶段目标：打破“只能人工在终端传标准 `.md`”的限制，打通**项目空间建表 + `.docx`/`.xlsx`/`.pdf`/`.txt` 转标准 Markdown + v3 表格保护切片 + 网页动态增删文档**。

---

## 目标

用户在 Web 界面选定一个项目后，直接上传 `.docx`、`.xlsx`、`.pdf`、`.md` 或 `.txt` 文档（如活动安排表、接口规范），系统自动标准化切片并实时生效，支持按单篇文档覆盖更新或删除。

## 任务清单

### 1. 独立库初始化与 V2 增量迁移
- 编写幂等迁移脚本 `migrations/002_v2_schema.sql`（严格对照 `00_V2总体规格.md` §4）。
- 在本地 MySQL 新建独立数据库 `knowledge_qa_v2`：先导入 `001_init.sql`（建基础 4 表），再执行 `002_v2_schema.sql`；确认 `projects` 表内含 `shared` 与 `go-gin`。
- **禁止改动**原 `knowledge_qa` 库。

### 2. 多格式转标准 Markdown 适配器（`ingest/convert.go`）
定义统一接口：`Convert(filename string, raw []byte) (markdown string, sourceType string, err error)`：
- **`.md` / `.txt`**：校验合法 UTF-8（若带 UTF-8 BOM 则剥离），直接返回；`.txt` 若无 Markdown 标题则保留段落结构，交由 v3 切片器兜底。
- **`.docx`**：使用纯 Go 解析库（如 `github.com/gomutex/godocx`）按文档顺序遍历段落与表格：
  - 将 Word 样式 `Heading 1 / 2 / 3`（或“标题 1 / 2 / 3”）映射为 `#`、`##`、`###`；
  - 将 Word 表格转成标准 Markdown 管道表格（`| 列1 | 列2 |`），前后加空行。
- **`.xlsx`**：使用 `github.com/qax-os/excelize/v2` 遍历每个非空工作表（Sheet）：
  - 每个 Sheet 输出为 `## {Sheet名}`，首行非空行作表头输出标准 Markdown 表格；自动跳过全空行/全空列。
- **`.pdf`**：使用纯 Go 解析库（如 `github.com/pdfcpu/pdfcpu` 或 `github.com/ledongthuc/pdf`，按页抽取文本并保留段落换行）：
  - **关键护栏（防静默乱码）**：若抽取出的有效文字字符数极少（例如每页平均 `< 30` 个可读字符，高度疑似纯图片扫描件）：
    - 若环境变量配置了 `LLM_VLM_MODEL`：可通过可选 VLM 转换钩子转写为 Markdown；
    - **若未配置 `LLM_VLM_MODEL`：直接返回明确错误**（`"检测到 PDF 疑似扫描件或无文本层，请先进行 OCR 或配置 LLM_VLM_MODEL"`），严禁把空文本或乱码写入数据库！
- 可选扩展：当环境变量 `CONVERT_ENGINE=markitdown` 时，允许通过 `exec.Command` 调用本机 `markitdown` CLI，但默认 `native` 模式必须纯 Go 零外部工具通过全部单测。
- `.env.example` 同步追加 V2 可选环境变量说明注释。

### 3. 切片器 v3（`ingest/chunk.go`）
**保留 `SplitMarkdown`（v1）与 `SplitMarkdownV2`（v2）不删**（保证现有单测通过），新增 `SplitMarkdownV3(text string) []ChunkPiece`：
1. **代码块保护**：继承 v2，` ``` ` 围栏内不识别标题、不从中间切断。
2. **Markdown 表格整体保护**：连续的 `|...|` 表格行（含分隔行 `|---|---|`）视作一个原子块，绝不在表格中部无表头切断：
   - 表格总字符 `<= 800`：整张表留在同一个切片内；
   - 超大表格 `> 800`：按行分片时，**每个子切片都自动复制保留原表头（前两行 `|...|` 与 `|---|`）和同一 `heading_path`**。
3. **无标题 / 超长段落递归切分与 Overlap**：
   - 优先按空行 `\n\n` 切；若单个非代码/非表格文本块本身仍 `> 800`（如无空行的长篇 `.txt` 纪要），按句末标点（`。！？\n`）递归拆到 `<= 800`；
   - 同一标题下二次拆分出的相邻子段之间，保留末尾 **80 字符重叠（Overlap）**，避免句子在边界处被切断失真。
4. **过短段合并**：继承 v2（`< 100` 字符且与下一段同父标题时合并）。

### 4. 文档热入库、去重、删除与缓存（`store/` + `api/`）
- **事务写/删**：
  - `InsertOrReplaceDocument`：计算内容 `SHA-256` 作为 `content_hash`。同一 `project_id` 下已存在相同 `filename` 且 `content_hash` 相同且未传 `overwrite=true` → 返回 `"文档内容未变更，已跳过重复导入"`；若传入 `overwrite=true`（或同项目同名内容变化）→ 在同一事务内删除旧 `chunks`、更新 `documents` 元数据与新 `content_hash`、写入新 `chunks`。
  - `DeleteDocument(id)`：事务内先删 `chunks WHERE document_id = ?`，再删 `documents WHERE id = ?`；若 `eval_questions.source_doc_id` 关联过该文档，返回受影响金标题计数提醒（不直接误删金标记录）。
- **轻量内存向量缓存（可选但推荐）**：`Store` 或 `Handler` 缓存已解析好的 `[]float64` 向量结构（带 `sync.RWMutex`），在新增/更新/删除文档时自动失效刷新，避免每次问答反复 `json.Unmarshal`。
- **HTTP 接口**：
  - `GET /api/projects`、`POST /api/projects`（创建项目校验 `slug` 仅允许小写字母/数字/连字符）
  - `GET /api/documents`（支持 `?project_slug=&status=`，返回文档列表、切片数、`doc_level`、`status`、`owner`、`updated_at`）
  - `POST /api/documents/upload`：支持 `multipart/form-data`（字段 `file`、`project_slug`、`doc_level`、`owner`、`overwrite`）或 JSON；返回 `{document_id, filename, project_slug, chunk_count, skipped, warnings}`
  - `PATCH /api/documents/:id`：修改 `status`、`doc_level`、`owner`、`replaced_by_doc_id`
  - `DELETE /api/documents/:id`：删除文档及切片

### 5. 前端轻量化接入（`static/index.html`）
- 保持原有极简白色风格，在顶部增加轻量页签切换：**「智能问答」** | **「资料库治理」**。
- 「资料库治理」页签包含：创建项目、上传文件（支持多格式选择 + 所属项目 + 文档层级 + 负责人）、文档列表（显示格式图标、切片数、`active/deprecated` 状态切换与删除按钮）。
- 底部角落的语料段数调用 `/api/chunks` 实时刷新（上传/删除后自动更新）。
