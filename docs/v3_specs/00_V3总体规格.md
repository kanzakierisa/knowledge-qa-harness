# 知识问答 Agent Harness — V3 总体规格（协作闭环与交付收尾版）

> **这份文档记录 V3 阶段的总体架构约束与兼容契约。** 阶段 12～13 的设计与实现均围绕本文档展开；
> 本规格在 V1（`stage8-delivered` 标签）与 V2（`stage11-delivered` 标签）已验收能力基础上继续演进；如阶段文档与本文档冲突，以本文档为准。

---

## 1. 项目定位、已落地底座与 V3 演进边界

本项目针对字节跳动「巨量引擎｜新生意创造者·AI挑战赛」赛题 5 —— **《为知识密集型、多项目并行团队构建知识问答 Agent Harness》**（面向内容消费场景的 AI 产品方向）。

### 1.1 已冻结底座（V1 + V2 已完成）

1. **V1 底座（阶段 1～8，封存于 `..\v1` / `master` 分支 / `stage8-delivered` 标签 / `knowledge_qa` 库）**：
   - Go + Gin + MySQL 8 单体可控流水线，双路检索（向量 + BM25）、句级 `[n]` 强校验与无据拒答。
   - `base52`（52 题金标集）四项核心指标均达到 100%。
2. **V2 底座（阶段 9～11，封存于 `..\v2` / `feat/v2-harness` 分支 / `stage11-delivered` 标签 / `knowledge_qa_v2` 库，详见 `docs/v2_iterations.md`）**：
   - **阶段 9**：`projects` 多项目空间、`.md`/`.txt`/`.docx`/`.xlsx`/`.pdf`（及可选 VLM）热转换、`SplitMarkdownV3` 代码块/表格保护切片、`content_hash` 防重与文档 CRUD。
   - **阶段 10**：指定项目硬隔离（目标项目 + `shared`）、`auto` 模式跨项目高分歧义主动澄清（`compare` 并排比对）、`doc_level` 权威度加权与 `deprecated` 废弃文档黄色警告。
   - **阶段 11**：构建 39 题独立对抗盲测集 `holdout`（含 13 题 `near_miss_refusal` 高分陷阱），上线多标识符覆盖增强（`ApplyMultiEntityCoverage`）、可选 R1 凸组合 Rerank（`RERANK_BASE_URL` 未配默认零开销关闭）与 **G1 单轮 Quote-First 结构化 JSON 输出**（`decision` 物理隔离拒答 + 逐字 `quotes` 校验 + 纯文本自动回退）。最终默认配置在 `base52`（40/40 命中、40/40 引用、40/40 可用、12/12 拒答）与 `holdout`（22/23 命中、23/23 引用、23/23 可用、16/16 拒答、`near_miss_refusal` 13/13=100%）上均实现**可答题误拒 0 条**。

### 1.2 V3 剩余目标（阶段 12～13）

1. **阶段 12（知识盲区雷达与协作闭环）**：线上拒答沉淀“团队知识盲区雷达”、答案句级荧光高亮、`👍/👎` 用户反馈一键转正活评测集（`question_set='feedback'`）、热更新覆盖文档触发 `Doc CI/CD` 局部回归。
2. **阶段 13（多项目演示沙箱、即插即用与竞赛交付）**：`corpus_v2/` 与 `scripts/seed_demo_v2.go` 沙箱一键灌库、Docker Compose 全栈编排、`--setup-ui` 零门槛引导、终版 `README.md` 与 3 分钟录屏脚本，并在 `11.25` 前完成竞赛合规核验。

### 这不是什么（红线不许破）

- ❌ 不是黑盒多智能体漫游框架。禁止引入 LangChain、LlamaIndex、AutoGen 等编排框架，禁止无上限 ReAct 循环。
- ❌ 不靠硬编码某个题目关键字或“强行覆盖拒答”刷指标。
- ❌ 不破坏 V1 与 V2 封存基线：**`master` 分支、`stage8-delivered`、`feat/v2-harness`、`stage11-delivered`、`migrations/001_init.sql`、`..\v1`、`..\v2` 以及原 MySQL `knowledge_qa` / `knowledge_qa_v2` 库均保持不动**；V3 全程在 **`feat/v3-harness`** 分支与独立数据库 **`knowledge_qa_v3`** 上演进。

## 2. 技术栈与 V3 依赖边界

| 项 | V3 选型与边界 | 说明 |
|---|---|---|
| 语言 | Go（1.22+） | 当前模块已使用 Go 1.26，保持原生标准库优先 |
| HTTP 框架 | Gin（`github.com/gin-gonic/gin`） | 延续 V1/V2 |
| 数据库 | MySQL 8（`github.com/go-sql-driver/mysql`） | 在 `001_init.sql` 之上增量执行 `migrations/002_v2_schema.sql`（如 V3 确需补索引/字段须幂等追加到新迁移或兼容逻辑，严禁改动 `001_init.sql`） |
| 向量与关键词计算 | Go 代码手写余弦相似度 + BM25（含进程内缓存，写入/删改文档时失效刷新） | 2,000 段以内内存计算毫秒级 |
| 已纳入白名单的多格式解析库 | - `.docx`：`github.com/gomutex/godocx`<br>- `.xlsx`：`github.com/xuri/excelize/v2`<br>- `.pdf`：`github.com/ledongthuc/pdf`<br>禁止再引入 CGO 依赖或重型编排框架 | 外部轻量 CLI（`CONVERT_ENGINE=markitdown`）与 VLM OCR 继续通过 `ingest.Converter` 接口与可选环境变量接入 |
| LLM / Embedding / 可选 Rerank / 可选 VLM | OpenAI 兼容 HTTP API，**全部走环境变量配置** | 代码与配置模板中**禁止硬编码任何 Key、地址、真实密码** |
| 前端 | 原生 HTML / CSS / JS，单页面多页签工作台，**禁止前端框架与外链 CDN** | `//go:embed` 内嵌打包；**严禁使用 `innerHTML` 拼接用户/文档不可信文本** |

## 3. 配置规范（严格向后兼容 V1/V2）

### 3.1 必需环境变量（5 项不变）

```text
LLM_BASE_URL      # 对话 OpenAI 兼容 API 地址，如 https://api.deepseek.com/v1
LLM_API_KEY       # 对话 API key
LLM_CHAT_MODEL    # 对话模型名，如 deepseek-chat
LLM_EMBED_MODEL   # embedding 模型名，如 text-embedding-v3
MYSQL_DSN         # V3 指向独立库 knowledge_qa_v3，如 root:pwd@tcp(127.0.0.1:3306)/knowledge_qa_v3?charset=utf8mb4&parseTime=true
```

**强约束**：常规启动 `config.Load()` 仍必须校验上述 5 个变量全部非空，缺任何一个直接报错退出并提示缺哪个（确保阶段 1 审计单测 `TestAuditStage1RequiredVariables` 永远通过）。

### 3.2 可选扩展环境变量

```text
EMBED_BASE_URL    # 独立 Embedding 平台地址（缺省回落 LLM_BASE_URL）
EMBED_API_KEY     # 独立 Embedding API Key（缺省回落 LLM_API_KEY）
HTTP_ADDR         # 监听地址，默认 :8080
RERANK_BASE_URL   # 可选：Cross-Encoder 重排 API（已实现 R1 Top 25 凸组合，未配则零开销跳过；当前 gte-rerank-v2 对 base52 有 -2.5% 负迁移故默认关闭）
RERANK_API_KEY    # 可选：重排 API Key（缺省回落 EMBED_API_KEY / LLM_API_KEY）
RERANK_MODEL      # 可选：重排模型名，缺省回落 gte-rerank-v2
LLM_VLM_MODEL     # 可选：扫描件 PDF / 图片转 Markdown 的多模态模型名
VLM_BASE_URL      # 可选：独立 VLM 地址（缺省回落 LLM_BASE_URL）
VLM_API_KEY       # 可选：独立 VLM Key（缺省回落 LLM_API_KEY）
CONVERT_ENGINE    # 可选：native（默认纯 Go） | markitdown
```

> 阶段 13 若提供 Web 端首次引导配置能力，只能通过显式标志（如 `--setup-ui` 或 `ALLOW_WEB_SETUP=true`）在“缺少模型 Key 时临时进入内存配置态”启用，绝不得破坏默认 `config.Load()` 的必填报错契约；`.env.example` 与 `scripts/quickstart.*` 严禁填入任何真实凭据。

## 5. V3 核心流程（架构图）

```text
               ┌──────────────── 离线/热更新：多格式文档入库 ────────────────┐
               │                                                             │
  MD/TXT/DOCX/XLSX/PDF/IMG → 格式转换器(转标准 MD) → SplitMarkdownV3(表格+代码保护)
               │                                                             │
               └→ content_hash 去重 → Embedding API → MySQL (project_id, status, level)
                                                         │
                                     [阶段 12: 若覆盖旧文档] → Doc CI/CD 局部回归

               ┌──────────────────── 在线：多项目问答链路 ────────────────────┐
               │                                                             │
  问题 + project_slug(或 auto)                                                │
       ↓                                                                     │
  [项目过滤] 指定项目 → 仅查 project + shared；auto → 查全库                  │
       ↓                                                                     │
  向量检索 + BM25 融合 (+ 多实体覆盖保底 / 可选 R1 凸组合 Rerank) → Top 5     │
       ↓                                                                     │
  [歧义拦截] auto 模式下 ≥2 个非 shared 项目同处高分竞争区？                  │
       ├→ 是 → 返回结构化歧义澄清响应（支持 compare 并排比对，不写入盲区）     │
       ↓ 否                                                                  │
  [阈值拒答] Top1 融合分 < 阈值？ ── 是 ──→ (仅线上 ask 写 knowledge_gaps) → 拒答
       ↓ 否                                                                  │
  G1 单轮 Quote-First JSON 生成（含治理/废弃标注，兼容纯文本回退）            │
       ├→ decision="refuse" → 返回固定拒答（不泄露解释文本，按线上 ask 记入盲区）
       ├→ decision="answer" → 校验 quotes 原文 + 抽取自然语言 answer → ValidateCitations
       ↓ 校验失败重试 1 次仍失败 → (仅线上 ask 记入 knowledge_gaps) → 拒答    │
       ↓ 通过                                                                │
  组装 deprecated 警告 warnings → 返回前端（阶段 12: 句级荧光高亮 + 👍/👎）   │
```

## 6. 评测指标体系与零回归红线

| 指标 | 定义 | 口径要求 |
|---|---|---|
| 检索命中率 | 可作答题中 `gold_chunk` 进入 Top 5 的比例 | `base52` 与 `holdout`、`feedback` 分别统计，互不混算 |
| 引用准确率 | 非拒答回答中句级引用全部合法的比例 | 复用 `generate.ValidateCitations` |
| 答案可用率 | 人工标注 `usable=true` 的比例 | **永不自动判分**；未标注返回 `null`，按 `eval_runs.batch_id` 严格分批统计 |
| 拒答正确率 | 应拒答题实际拒答的比例 | **必须单独守住 `holdout` 的 `near_miss_refusal`（13 题）= 100%** |
| 误拒率（观测） | 可作答题却被拒答的比例 | 阶段 11 终版已把 `base52`（40 题）与 `holdout`（23 题）误拒双双降至 `0` |

**零回归红线**：阶段 12、13 的所有结构改动与演示语料导入，若影响核心检索/生成链路，必须通过 `go vet ./...`、`go test -count=1 ./...`（含真库临时 `*_test` 集成测试）以及 `base52` + `holdout`（含 `near_miss_refusal` 100%）回归验证。

## 7. V3 HTTP 接口契约

### 已上线接口（V1 + 阶段 9～11，严禁破坏兼容）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/ask` | 支持 `project_slug`（空/`auto` 为自动路由）与 `compare`；返回 `answer`、`citations`、`refused`、`retried`、`project_resolved`、`ambiguity`、`warnings`（阶段 12 仅此处 `recordGap=true`） |
| `GET` | `/api/chunks` | 保留返回 `{"total": N}`，可选 `?project_slug=` |
| `POST` | `/api/eval/run` | 支持 `?set=base52\|holdout\|feedback\|all`（默认 `base52`），按 `batch_id` 隔离，**禁止写入 `knowledge_gaps`** |
| `POST` | `/api/eval/mark` | 接收 `{run_id, usable}` 人工标注 |
| `GET` / `POST` | `/api/projects` | 查询项目列表 / 创建项目 |
| `GET` / `POST` | `/api/documents` / `/api/documents/upload` | 列出文档 / 多格式热上传（阶段 12 覆盖更新附带 `regression_summary`） |
| `PATCH` / `DELETE` | `/api/documents/:id` | 更新治理状态与替代文档 / 事务删除文档与切片 |

### 阶段 12 待新增接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` / `PATCH` | `/api/gaps` / `/api/gaps/:id` | 按 `hit_count DESC, last_asked_at DESC` 查看团队知识盲区与近似文档线索；标记 `resolved`/`ignored` |
| `POST` / `GET` | `/api/feedback` | 提交 `👍/👎` 用户反馈 / 列出待审负面反馈队列 |
| `POST` | `/api/feedback/:id/promote` | 审阅转正负面反馈为 `eval_questions`（`question_set='feedback'`）并回填 `promoted_question_id` |

### 阶段 13 已上线扩展接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` / `POST` | `/api/setup/status` / `/api/setup` | 内存态模型配置状态查询（脱敏无密钥）与应用（`--setup-ui` / `ALLOW_WEB_SETUP=true`） |
| `GET` / `PATCH` / `DELETE` | `/api/sessions` / `/api/sessions/:id` | 多轮任务会话列表、详情恢复、置顶、重命名与级联删除 |
| `GET` | `/api/stats/online` | 全量真实线上提问的客观统计聚合 |
| `GET` | `/api/documents/:id` | 单篇文档全文预览与有序切片查询 |

## 9. 开发与回归纪律

1. **阶段隔离**：每次迭代聚焦单一目标，开发前先确认处于 **`feat/v3-harness`** 分支、连接的是 **`knowledge_qa_v3`** 数据库。
2. **先测试后过关**：每个阶段结尾必须跑通本阶段全部验收命令，并执行 `go vet ./...` 与 `go test -count=1 ./...`（含无 MySQL 与临时 `*_test` 真库两种模式）回归，全部通过才准进入下一阶段。
3. **禁止静默兜底掩盖错误**：解析失败或接口异常必须明确反馈原因；不得在测试中放松断言或绕过校验。
4. **全程保持零凭据入库**：任何脚本、Docker 配置、示例文件、文档及完整 Git 历史均不得包含真实 Key、密码或私有路径凭据。
