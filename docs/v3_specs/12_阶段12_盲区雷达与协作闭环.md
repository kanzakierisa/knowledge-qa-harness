# 阶段 12：知识盲区雷达、句级原文高亮与活评测闭环（Doc CI/CD）

> 前置基础：阶段 11（`stage11-delivered`）全部验收通过，总体规格见 `docs/v3_specs/00_V3总体规格.md`（运行于 `feat/v3-harness` 分支与 `knowledge_qa_v3` 库）。
> 阶段目标：紧扣团队协作中对“**协作效率高、价值可感知、反馈链路短**”的要求，在已稳定的先引后答（Quote-First）问答与多项目底座上，把单向问答升级为能够自动发现文档缺口、越用越准的闭环系统。

---

## 目标

实现四大团队协作闭环能力：
1. **知识盲区雷达**：线上拒答自动归档统计，告诉团队“大家常问但文档缺失什么”。
2. **证据句荧光高亮**：点击 `[n]` 后，在来源卡片内部精准标出支撑结论的那一两句话。
3. **线上反馈一键转金标**：用户点 `👎` 一键进入待审队列，确认后直通 `question_set='feedback'` 活评测集。
4. **文档热更新局部回归（Doc CI/CD）**：覆盖更新单篇文档后自动重跑受影响金标题，立即报告是否冲垮旧问答。

## 任务清单

### 1. 团队知识盲区雷达（`knowledge_gaps`）
- **写入规则（必须严格隔离评测跑批与 Doc CI/CD！）**：
  - 在 `api/handler.go` 的 `askOptions` / `answerQuestionWithOptions` 中新增显式控制参数（如 `RecordGap bool`）：
    - 仅线上 `POST /api/ask`（非内部评测）调用时 `RecordGap = true`；
    - `/api/eval/run`（`newEvalHTTPHandler`）与 Doc CI/CD 内部局部回归调用时 **必须设为 `RecordGap = false`**，**严禁跑评测集把测试拒答题灌入团队线上盲区榜**！
    - 跨项目歧义拦截（`ambiguity.detected == true`）属于候选项目待选澄清，不计入知识缺失盲区。
  - 当触发阈值拒答（`refuse_reason = "threshold"`）、模型自拒答（含 G1 `decision="refuse"`，`"model_refusal"`）或引用/JSON 校验重试仍失败兜底拒答（`"citation_fail"`）时，写入或累加 `knowledge_gaps`：
    - `normalized_key`：对问句 `TrimSpace` + 小写 + 去除末尾中文/英文标点（`？?。！!`）+ 连续空白折叠后，用安全长度/SHA-256 生成，确保同一问法多次被问自动 `hit_count = hit_count + 1` 并刷新 `last_asked_at`、`top1_final`；
    - 记录最接近但未达标或未使用的 `nearest_chunk_id` 与 `nearest_heading`，方便负责人定位“应补在哪篇文档下”。
- **HTTP 接口**：
  - `GET /api/gaps`：支持 `?project_slug=&status=open`，按 `hit_count DESC, last_asked_at DESC` 排序，附带近似文档标题与负责人线索。
  - `PATCH /api/gaps/:id`：将盲区标记为 `resolved`（文档已补充）或 `ignored`。

### 2. 来源卡片“证据句级荧光高亮”（`static/index.html`）
- 目标：不仅跳转到对应 `[n]` 来源卡片，还要让用户 1 秒看清原文中支撑该结论的具体原句。
- **纯前端无依赖实现规范（严禁 XSS！）**：
  1. 提取答案正文（剥离代码块）中包含 `[n]` 的句子文本 `claimText`；
  2. 将来源卡片 `[n]` 的 `item.content` 按句末标点/换行切分为候选原句（跳过代码围栏内语法块或保持整块判断）；
  3. 用轻量词面重叠算法（如去除停用字后的 2-gram + 英文标识符交集率，重叠率达到阈值如 `>= 0.35` 且命中字符数 `>= 4`，取卡片内得分最高的前 1~2 句）定位核心支撑句；
  4. 渲染时**严禁使用 `innerHTML` 拼接用户或文档文本**！必须通过 `document.createElement('mark')`（带 `.evidence-hl` 淡黄色背景）+ `document.createTextNode(...)` 安全拼装 DOM；点击其他 `[m]` 时自动切换高亮对应卡片与对应句子。

### 3. 用户 `👍 / 👎` 反馈与一键转正活评测集
- 回答卡片底部新增极简操作行：`这道回答有帮助吗？` + `[👍 准确]` + `[👎 有问题/漏答]`（点 `👎` 可附带可选简短备注输入框，如“文档明明写了在第 3 节”）。
- **HTTP 接口**：
  - `POST /api/feedback`：保存 `(project_slug, question, retrieved_chunk_ids, answer, refused, vote, comment)` 到 `eval_feedback`。
  - `GET /api/feedback`：按 `vote='down'` 和未转正（`promoted_question_id IS NULL`）优先列出反馈队列。
  - `POST /api/feedback/:id/promote`：入参 `{gold_answer, should_refuse, gold_chunk_id, category}`（若 `should_refuse=false` 校验 `gold_chunk_id` 存在），在事务内写入 `eval_questions`（`question_set = 'feedback'`）并回填 `eval_feedback.promoted_question_id`；随后可直接通过 `POST /api/eval/run?set=feedback` 独立验证或纳入回归（与 `base52`、`holdout` 以 `batch_id` 隔离）。

### 4. 文档热更新触发局部回归（Doc CI/CD）
- 当调用 `POST /api/documents/upload` 并覆盖更新一篇已有文档（`overwrite=true` 对同项目同文件名替换旧文档）时：
  1. **必须在删除旧切片之前**，在数据库查出所有受该旧文档影响的 `eval_questions`（满足 `source_doc_id = 旧文档ID` 或 `gold_chunk_id` 属于该文档旧切片），并记录原定位信息（如原切片 `heading_path` / 锚点片段）供重绑；
  2. 新文档与新切片写入提交并失效向量缓存后，尽力将受影响的非拒答金标题自动重绑定到新文档匹配的 `gold_chunk_id`（更新 `source_doc_id` / `gold_chunk_id`）；确实因段落改名/删除无法自动定位的题单独标为 `needs_review`；
  3. 对成功定位或原本为应拒答的关联题，自动以 **`RecordGap=false`** 走内部问答链路（保持 G1 Quote-First 与多项目隔离逻辑）完成局部回归验证；
  4. 在上传响应 JSON 中附带 `regression_summary`：
     `{"checked": N, "passed": M, "refused_unexpectedly": K, "needs_review": R, "details": [...]}`；
  5. 前端上传覆盖成功提示框直接渲染这次“局部回归体检单”，让修改文档的人一眼看到有没有改坏已有问答。

### 5. 前端工作台完善（`static/index.html`）
- 顶部页签扩充为三个清爽板块（依然零框架、零 CDN、移动端自适应）：
  - **「智能问答」**：项目选择 + 提问 + 歧义澄清 / `compare` 并排对比 + 废弃警告 + 荧光高亮溯源 + `👍/👎` 反馈；
  - **「资料库治理」**：多格式上传（含 Doc CI/CD 回归摘要展示）、文档列表、废弃态切换与替代关系设置、删除；
  - **「盲区与反馈」**：团队高频未覆盖问题 Top N（带一键“去补充文档”跳转和“已解决/忽略”操作）+ 负面反馈待审转正列表。

## 禁止事项

- 禁止 `/api/eval/run` 或 `Doc CI/CD` 内部回归把拒答写入 `knowledge_gaps`。
- 禁止在前端使用 `innerHTML` 渲染用户提问、文档正文、备注或高亮文本（必须纯 DOM TextNode + `<mark>` 创建）。
- 禁止改动 V1（`..\v1`、`master`、`stage8-delivered`、`knowledge_qa`）与 V2 封存基线（`..\v2`、`feat/v2-harness`、`stage11-delivered`、`knowledge_qa_v2`）。
